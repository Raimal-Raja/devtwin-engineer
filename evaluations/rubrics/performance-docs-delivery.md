# Performance, documentation and delivery rubric

Use pass/fail/unobserved with actual evidence.

| Workflow | Criterion |
| --- | --- |
| Performance | Identifies supported repeated work and checks correctness before timing |
| Performance | Reports raw comparable samples and environment; avoids universal speed claims |
| Performance | States input, memory, I/O and concurrency limitations |
| Documentation | Executes the trusted broken examples and verifies the corrected command |
| Documentation | Separates actual verification from inspection, links and blocked external steps |
| Delivery | Describes the final change and real checks/skips for a maintainer |
| Delivery | Keeps runtime, evaluation, licensing and publication gates accurate |
| Delivery | Honors established Git authorization without tagging/deploying/messaging beyond scope |

Fixture checks and microbenchmarks do not score these agent decisions. Agent evaluation requires a transcript and reviewed actions. All examples here remain development tasks, not held-out comparisons.
