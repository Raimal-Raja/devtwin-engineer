# Incremental roadmap

Current work prioritizes Codex and the standalone browser workspace. Claude execution is deferred by explicit user choice. Completed increments are committed and pushed to the private repository after verification.

Implemented and exercised:

- Thirteen workflow references with tasks, rubrics, fixtures, evidence requirements, checks and failure boundaries. The resource registry is part of the unified local gate.
- Bounded helpers, explicit archive allowlists, integrity checks, project installers and shared Codex/Claude plugin wrappers.
- Codex library/HTTP repairs, preservation, blocked reporting, automatic selection and expanded synthetic reviews. Native plugin installation/discovery is separate evidence.
- Fresh Codex order-dependent repair and untrusted-source/unsupported-project checks, with parent acceptance and protected-file hashes.
- Public catalog/setup dashboard and validated development downloads.
- Internal authenticated loopback workspace: selected ZIP ingestion, explicit provider consent, source analysis, reviewed single-file proposals and candidate export.
- NVIDIA synthetic live inference; Groq/Gemini adapters with simulated tests. No automatic fallback or paid billing upgrades.
- Commit-pinned GitHub selected-file import and real public-repository browser preview; no GitHub writes.

Before deploying the complete browser agent:

1. Local Docker execution is validated; broader production containment remains pending.
2. The local bounded repair loop is connected and live-tested; see repair-loop.md.
3. Configure and live-test a selected free-plan provider through backend secrets; Groq/Gemini keys remain absent.
4. Prepare production authentication, jobs/usage limits, privacy controls and suitable free hosting.
5. Validate deployment gates, preserve existing public website access and refresh development downloads.

Independent 15–20 task baseline comparisons, authorized pilot feedback, broader platform/plugin execution and formal licensing/release remain separate gates. No effectiveness improvement is claimed from development examples. No pilot invitations, repository visibility changes or license selection are authorized implicitly.

See [capability prerequisites](capability-prerequisites.md), [completion status](completion-status.md) and [deployment readiness](deployment-readiness.md). Historical failed/inconclusive attempts remain in evaluation results; later successful checks do not erase them.
