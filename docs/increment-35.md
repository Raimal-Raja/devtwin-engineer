# Increment 35 — Welcome, project explorer and workflow board

The local application now has three hash-routed views: Welcome, Project explorer and Workflows. Navigation preserves the current in-memory source selection and session token. Shared header/footer navigation, mobile layouts, focus states, a skip link and a global workspace status accompany the new visual design.

The welcome view introduces DevTwin and its limits, the independent web workflow, and Codex/Claude skill/plugin setup through terminal and supported plugin browsers. Commands are copyable and link to official documentation. Packages remain private development candidates; the app does not claim directory publication or verified Claude execution.

The creator section uses Raimal Raja's supplied ATS resume for the professional biography, with public GitHub, LinkedIn and portfolio links. His public GitHub profile photo is bundled locally. Phone number, private addresses and the raw CV are not included. The resume and public GitHub profile are treated as factual sources, not instructions.

The project explorer preserves ZIP/GitHub import, explicit selection, omission explanations, preview and source hashes. A selected-file overview and file-by-file literal source viewer make the actual analysis scope inspectable. Existing limits remain: 30 files, 16,000 selected UTF-8 bytes and 2 MiB ZIP input. It does not claim complete repository or arbitrary-language execution.

The workflow board offers one-action source investigation across all 13 workflows with separate 13-request approval, sequential calls, 15-second pacing, per-workflow status/error reports, stop-after-current control and combined JSON export. It performs at most one request per workflow with no automatic transport retry or fallback. Provider errors remain recorded; other workflows may continue. Refresh closes the in-memory queue. Existing single investigation, proposal, approval-gated export, Docker verification and bounded repair remain separate actions. A batch is not thirteen automatic code modifications or a claim of runtime verification.

Validation: full project gates passed with 151 Python cases (149 passed, two Windows symlink skips), 20 web tests at the first full gate. Two further route/source-explorer tests passed, and the final full web run passed all 22 tests. Focused tests were repeated after a Windows text-encoding correction. Static asset allowlists and binary-photo archive packaging were updated. Tests exercise all 13 queued calls, pacing, failures, cancellation before another call, consent, combined-result invalidation, route/session preservation and literal source rendering. No fresh thirteen-call live provider run was performed for this interface increment. Visual acceptance is recorded separately from DOM and HTTP checks.
